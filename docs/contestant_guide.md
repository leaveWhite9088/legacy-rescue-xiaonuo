# 选手须知（被测模型一条龙操作指南）

本基准采用**单次执行者收尾 + 盲评后统一定稿模式**。你作为被测模型，在仓库根目录自行完成“起局 → 沙盒排障 → 收工封包 → 计时校验与生成匿名盲评包”全流程（详见 [AGENTS.md](../AGENTS.md)）。

## 1. 起局与工作边界
- 起局命令会将纯净的带病多代遗留系统派发到 `sandbox/<你的模型名-r1>/` 并打下起始时间戳。
- **在执行收工封包命令之前，你的所有读取、搜索与修改操作必须严格限制在 `sandbox/<你的模型名-r1>/` 内部**，严禁读取或搜索 `src/scoring/`、`src/builders/`、`reference/`、`configs/` 等目录。

## 2. 沙盒内需要原地交付的 4 项成果
1. **修复后的跨层源码与活跃前端视图文件**：顺着日志、中间件、门面层、兼容桥接层、事件钩子与调用链理清真实活跃链路定位底层根因，避免误改历史废弃死代码或做大面积无关重构。
2. **安全订正后的数据库 `data/yunce_billing.db`**：
   - 将 `2026-11`（未结清开放账期）中的异常错账、重复单、卡死单与失衡钱包精准修平；
   - **严禁直接修改或覆写 `2026-09`、`2026-10`（已封账账期）的历史账单与归档总额**，历史封账差额请按财务审计规范在当前开放账期生成调账记录；
   - **保留存量老数据兼容**：不得删改 2024 年迁移老租户与字符串金额兼容保护逻辑，且勿开启未完备的实验灰度开关；
   - **识别伪反馈与越界需求**：不得把原本符合产品与税务规则的累进阶梯、退订不退费、价外增值税、滞纳金逻辑改坏。
3. **新增回归测试（`tests/` 目录下）**：编写能复现原暗病并在修复后通过的测试，同时确保沙盒原有单元测试全部绿灯。
4. **填写完整的 `事故排查与处置说明.md`**：按模板写明每条反馈的真伪判定、底层根因、修复方案及数据订正边界。

## 3. 收工封包与盲评打包收尾
- 完成排障后运行 `finish_rescue.py` 冻结快照并记录耗时与词元用量；
- 随后仅运行 `timing_audit.py` 与 `judge_pack.py` 生成匿名盲评包，将生成的 `leaderboard/blind/<pack_id>/` 路径汇报给用户即可（**不要运行 `score_delivery.py`、`judge_submit.py` 或 `finalize.py`**；正式脚本评分与总分合成将在盲评结束后由 `finalize.py` 统一完成）。
