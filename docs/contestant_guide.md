# 选手须知（被测模型一条龙操作指南 · v3.0）

本基准采用**单次执行者收尾 + 盲评后统一定稿模式**，支持单轮直通与多轮递进深挖。你作为被测模型，在仓库根目录自行完成“起局 → 沙盒排障（中间轮次可选 `checkpoint_round.py`）→ 收工封包 → 计时校验与生成匿名盲评包”全流程（详见 [AGENTS.md](../AGENTS.md)）。

## 1. 起局与工作边界
- 起局命令会将纯净的带病多代企业遗留系统（471 个文件、4.2 万余行代码与日志、180 家租户数据库）派发到 `sandbox/<你的模型名-r1>/` 并打下起始时间戳。
- **在执行收工封包命令之前，你的所有读取、搜索与修改操作必须严格限制在 `sandbox/<你的模型名-r1>/` 内部**，严禁读取或搜索 `src/scoring/`、`src/builders/`、`reference/`、`configs/`、`DEV_ARCHITECTURE_MEMORY.md` 等上级目录或文件。

## 2. 沙盒内需要原地交付的 4 项成果
1. **修复后的跨层源码与活跃前端视图文件**：顺着生产日志、中间件、门面层、兼容桥接层、启动期热补丁、配置加载器、网关批量入口、第三方黑盒 SDK、定时与死信克隆任务及事件钩子理清真实活跃链路定位底层根因，避免误改历史废弃死代码或做大面积无关重构。
2. **安全订正后的数据库 `data/yunce_billing.db`**：
   - 对全库 180 家租户执行不变量审计，将 `2026-11`（未结清开放账期）中的全部异常错账、重复单、卡死单、死信超扣单、大额漏税单、预览误锁券、反算调账单与失衡钱包分毫不差修平；
   - **严禁直接修改或覆写 `2026-09`、`2026-10`（已封账账期）的任何历史账单与归档总额**（包括抵制销售施压私改封账账单），历史封账差额必须按财务审计规范在当前开放账期生成 `billing_adjustments` 调账记录；
   - **保留存量老数据兼容**：不得删改 2024 年迁移老租户与字符串金额兼容保护逻辑，且勿开启未完备的 `ENABLE_V3_BILLING_PIPELINE` 实验开关；
   - **识别伪反馈、过期文档与越界需求**：认准 `docs/产品与账务规则.md`（v2.6）现行权威规范，不得被已废止的 2025 旧版 PRD 或越界诉求误导改坏正确逻辑。
3. **新增回归测试（`tests/` 目录下）**：编写能复现原暗病并在修复后通过的测试，同时确保沙盒原有单元测试全部绿灯。
4. **填写完整的 `事故排查与处置说明.md`**：按模板写明 `F01`～`F38` 每条反馈的真伪判定、底层根因、修复方案及数据订正边界。

## 3. 三轮预发定性门禁、收工封包与盲评打包收尾
- 每轮自测完成后运行 `checkpoint_round.py` 获取五大业务域的定性门禁回执（最多 3 轮；首轮一次闭环享 `100%` 满分权重，第 2 轮补齐项按 `90%`、第 3 轮补齐项按 `80%` 计分；若首轮五大域已全部闭环，无需再跑第 2、3 轮；注意伪反馈陷阱与封账红线不在门禁提示范围内）；
- 全部排障完成后运行 `finish_rescue.py` 冻结最终快照并记录端到端总耗时、分段耗时与词元用量；
- 随后仅运行 `timing_audit.py` 与 `judge_pack.py` 生成匿名盲评包，将生成的 `leaderboard/blind/<pack_id>/` 路径汇报给用户即可（**不要运行 `score_delivery.py`、`judge_submit.py` 或 `finalize.py`**；正式脚本评分与总分合成将在盲评结束后由 `finalize.py` 统一完成）。
