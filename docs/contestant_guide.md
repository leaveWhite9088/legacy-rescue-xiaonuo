# 选手须知（被测模型一条龙操作指南 · v4.1）

本基准采用**三轮预发定性门禁 + 单次执行者收尾 + 盲评后统一定稿模式**。你作为被测模型，在仓库根目录自行完成“起局 → 沙盒深度排障（最多 3 轮 `checkpoint_round.py` 定性巡检）→ 收工封包 → 计时校验与生成匿名盲评包”全流程（详见 [AGENTS.md](../AGENTS.md)）。

## 1. 起局与防作弊工作边界
- 起局命令会将待排障的企业遗留工程派发到 `sandbox/<你的模型名-r1>/` 并打下不可伪造的起始时间戳 `t0`。
- **在执行收工封包命令之前，你的所有读取、搜索与修改操作必须严格限制在 `sandbox/<你的模型名-r1>/` 内部**，严禁读取、列出或搜索 `src/scoring/`、`src/builders/`、`reference/`、`configs/`、`runs/`、`leaderboard/`、`DEV_ARCHITECTURE_MEMORY.md` 等上级目录或文件。

## 2. 沙盒内需要原地交付的 4 项成果
1. **外科手术式修复全链路活跃代码**：
   - 理清多代演进仓库中的真实挂载入口与调用链，排查工单反馈及未报障的系统潜伏缺陷；
   - 仔细核对 `docs/` 下不同时期业务制度与技术文档的生效范围及修订关系，保护合法的存量特例与旁路约定，切勿误改未挂载的历史残留代码或做大面积破坏性重写。
2. **编写全库对账脚本合规订正数据库 `data/yunce_billing.db`**：
   - 对线上数据库执行跨表不变量与账务平衡核查，修平开放账期内的异常数据与子账本差异，严守财务封账纪律。
3. **补充高质量细粒度回归测试（`tests/` 目录下）**：编写能在未修复原件上真实失败抓错、并在修复后绿灯通过的独立 `test_*` 方法，同时确保既有单元测试套件保持全绿。
4. **填写完整的 `事故排查与处置说明.md`**：逐条覆盖 `F01`～`F68` 全部反馈的真伪定性与依据，并详列自主挖掘的潜伏缺陷及全库数据订正台账。

## 3. 三轮预发定性门禁、收工封包与盲评打包收尾
- 每轮自测完成后可运行 `checkpoint_round.py` 获取七大业务域的定性门禁回执（最多 3 轮；首轮一次闭环享 `100%` 满分权重，第 2 轮补齐项按 `85%`、第 3 轮补齐项按 `70%` 计分；若首轮七大业务域均已显示「已闭环」，核验报告后直接封包即可；注意回归防误伤与合规红线不在门禁提示范围内）；
- 全部排障完成后运行 `finish_rescue.py` 冻结最终快照并记录端到端总耗时、分段耗时与词元用量；
- 随后仅运行 `timing_audit.py` 与 `judge_pack.py` 生成匿名盲评包，将生成的 `leaderboard/blind/<pack_id>/` 路径汇报给用户即可（**严禁运行 `score_delivery.py`、`gatekeeper.py`、`judge_submit.py` 或 `finalize.py`**）。
