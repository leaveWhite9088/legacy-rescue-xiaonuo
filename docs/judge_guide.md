# 评委盲评指南（D 层：20 分 · v3.0）

## 盲评原则
- 评委**仅**查看 `leaderboard/blind/<pack_id>/` 下的匿名事实卡（`case-XX.md`），不得查阅模型映射表（`leaderboard/blind-maps/`）或中心评审日志（`leaderboard/reviews.jsonl`）。
- 事实卡已展示客观核验摘要（`BUG-01`～`BUG-15` 探针通过情况、12 项脏账与封账红线核验、16 项静音回归保护、代码改动规模、突变测试结果）及选手《事故排查与处置说明》原文。

## 评分维度与锚点
1. **D1 根因归因准确度（0～8 分）**
   - `3～4 分`：仅定位到表层显性缺陷，遗漏启动期紧急猴子补丁、克隆扣款分支、动态配置字符串漂移、只读接口写副作用、第三方黑盒 SDK 截断或资源泄漏等深层暗病。
   - `6 分`：定位出绝大多数跨层暗病，调用链分析与客观探针事实一致。
   - `8 分`：15 大暗病根因全部定位精准、跨层证据链完整清晰，无虚构或张冠李戴结论。
2. **D2 伪反馈、过期文档与规则边界定力（0～6 分）**
   - `3 分`：识别出部分伪反馈，但对过期 PRD 或税务合规边界判断含糊。
   - `5 分`：准确区分 `F25`～`F38` 中的累进阶梯、退订不退费、v1 老租户保护、统一滞纳金、正常小额价外税、Webhook 瞬态重试成功、2025 废止旧 PRD 配额误导、销售施压私改封账历史单、未完备 V3 实验开关、实收现金返佣、境外/全赠金禁开专票及企业保底消费，未误改正确逻辑。
   - `6 分`：甄别依据扎实，明确引用现行权威《产品与账务规则 v2.6》与生产日志证据给出清晰定性。
3. **D3 修复与数据订正方案的工程合理性（0～6 分）**
   - `3 分`：代码能跑通但改动规模偏大、误碰死代码目录，或 11 处开放期脏账订正有遗漏。
   - `5 分`：改动外科手术精准、`2026-11` 开放期 11 处脏账全部修平、严守 `2026-09` / `2026-10` 已封账红线（含 `INV-202610-0018` 不动与 `INV-202609-0012` 跨期调账）。
   - `6 分`：修复简洁优雅、并发锁粒度与幂等设计合理、跨期调账与回归测试完备可审查。

## 提交命令
```sh
python src/scoring/judge_submit.py --pack-dir leaderboard/blind/<pack_id> --case-id case-01 \
  --judge-id <评委ID> --judge-model <评委模型> \
  --D1 <0-8> --D2 <0-6> --D3 <0-6> --evidence "[引用的事实卡证据]" --note "<简短评语>"
```
