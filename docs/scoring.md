# 计分与时间维度细则（满分 100 分）

唯一配置源见 [`configs/benchmark.json`](../configs/benchmark.json)。

## 评分生命周期：盲评先行，最后一键统一定稿合成
1. **选手收尾阶段**：选手运行 `finish_rescue.py` 冻结交付快照后，仅运行 `timing_audit.py` 与 `judge_pack.py` 提取脱敏探针通过状态写入匿名盲评包（`leaderboard/blind/<pack_id>/`），**此阶段不计算也不落盘正式得分文件**。
2. **盲评阶段**：独立评委仅阅读匿名盲评包并通过 `judge_submit.py` 提交主观分 `D`（写入 `leaderboard/reviews.jsonl`）。
3. **最终定稿与合成阶段**：所有盲评完成后，评测发起人手动运行 `python leaderboard/finalize.py`，一次性对冻结交付物重新执行官方脚本客观分定稿（`A/B/C/T` 共 80 分，落盘 `runs/<run_id>/评分.json`）并与盲评 `D` 分（20 分）统一合成为 100 分制总分，生成裁决留档与总榜。

## 总分构成：客观自动分（80）+ 盲评主观分（20）

### A 层：跨层根因修复与脏账订正（35 分，机器自动判分）
- **A1 暗病根因修复（25 分）**：覆盖 7 个跨层连环暗病（`BUG-01` 4.5 分、`BUG-02` 4.0 分、`BUG-03` 4.0 分、`BUG-04` 3.0 分、`BUG-05` 3.5 分、`BUG-06` 2.5 分、`BUG-07` 3.5 分）。每个暗病由原故障复现、变体防作弊刺探（如非零超额分段、并发屏障撞车、双写路径穿越绕过）与底层不变量断言组成。
- **A2 线上脏账审计与封账红线（10 分）**：
  - 在 128 租户、167 张账单的线上快照中自主定位并修平 `2026-11`（`OPEN`）7 处受灾错账/重复单/卡死单/失衡钱包：共 8.0 分（逐项精确校验）。
  - `2026-09`、`2026-10`（`CLOSED`）封账红线、历史差额跨期调账与健康租户免误伤：2.0 分（已封账账单与归档总额必须 100% 未被改动，在 `billing_adjustments` 生成 `-20000` 分跨期调账，且未误伤正常价外税租户账单）。直接篡改已封账记录触发严重违规标记。

### B 层：零误伤与多子系统静音回归（20 分，机器自动判分）
- 覆盖 12 项回归探针：双门户可达性、伪反馈与越界需求保护（`F11` 超额累进阶梯、`F12` 退订不退月费、`F13` 2024 v1 异构老租户兼容、`F14` 统一 5% 滞纳金、`F15` 价外 6% 增值税计税引擎）、大客户最低保底协议、渠道伙伴返佣、总账借贷平衡、数电发票与双人审批流、经营分析与 FinOps 毛利及 SOX 内控诊断、以及全量单元测试绿灯。
- 若触发破坏老数据兼容、误改伪反馈/税率规则或篡改已封账记录等严重违规标记，B 层分数封顶并施加 `0.7` 总分惩罚系数。

### C 层：外科手术度与突变测试（10 分，机器自动判分）
- **C1 外科手术精准度（5 分）**：统计源码有效变更行数（不含测试、日志与数据文件）。`55～420` 行满分；`420～850` 行线性降至 2.5 分；`850～1600` 行线性降至 0 分；未改代码 0 分。
- **C2 新增测试突变检验（5 分）**：提取选手新增/修改的测试文件，先在**未修复原件**上运行（必须失败抓错），再在**交付件**上运行（必须通过）。

### T 层：端到端排障效率（15 分，机器自动判分）
- 端到端墙钟耗时 `elapsed`（从 `start_rescue.py` 的 `t0` 到 `finish_rescue.py` 的 `t1`）。
- 满分基准 `M = 30` 分钟，半衰期 `H = 35` 分钟：`T_raw = 15`（`elapsed <= 30`），否则 `15 * 0.5^((elapsed - 30) / 35)`。
- **核心成果联合封顶**：`T = min(T_raw, 15 * (A / 35) * (B / 20))`。未修好核心问题或弄崩回归时，无法靠秒退拿高时间分。

### D 层：诊断归因与处置分寸（20 分，匿名盲评）
- **D1 根因归因准确度（8 分）**
- **D2 伪反馈与规则边界定力（6 分）**
- **D3 修复与数据订正方案的工程合理性（6 分）**
