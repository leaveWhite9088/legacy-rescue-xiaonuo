# 云策企业订阅与阶梯计费账务中心 — 产品与账务规则（现行权威规范 v2.6）

> **效力声明（2026-Q3 起正式生效）**：本文档结合《2026_Q3_财税合规与资费标准修订决议》汇编，为线上计费、网关归集、钱包清结算、税务开票与财务关账的**唯一现行权威准则**。凡 `docs/` 下标有“2024 备忘”或“2025 历史归档 PRD”中与本文档不一致的旧口径，一律以本文档为准。

## 一、标准套餐、阶梯计费与框架合同
1. **标准月度套餐**：
   - `STARTER`（基础版）：199 元/月（`19900` 分），含 `10,000` 次 API 调用（注：2025 年短期推广期曾试行 15,000 次，已于 2026-Q3 正式废止并统一恢复为 `10,000` 次）。超额部分按超额累进阶梯计费：超额 `1～10,000` 次 `0.03` 元/次；超额 `10,001～50,000` 次 `0.02` 元/次；`50,000` 次以上 `0.01` 元/次。
   - `PRO`（专业版）：599 元/月（`59900` 分），含 `50,000` 次 API 调用。超额 `1～50,000` 次 `0.02` 元/次；`50,000` 次以上 `0.01` 元/次。
   - `ENTERPRISE`（企业版）：1,999 元/月（`199900` 分），含 `300,000` 次 API 调用。超额部分统一 `0.01` 元/次。
   - **累进原则**：所有套餐超额计费均采用**超额累进阶梯（Progressive Marginal Tiering）**，分段计算各区间费用后求和，绝非按最高档单价全量倒推。
2. **大客户最低消费框架合同（`enterprise_contracts`）**：
   - 签署有效框架合同（`status='ACTIVE'`）的大客户享有专属超额费率折扣（`custom_overage_discount_bps`）；若当期折后税前小计低于合同月度保底消费（`min_monthly_commit_cents`），系统自动按月度保底金额补齐税前基数。
3. **套餐升降配、运行期配置开关与退订规则**：
   - 同周期内**升级**套餐：默认必须按剩余周期天数比例折算补收差价（`proration_cents`）。仅当运行期配置项 `waive_upgrade_proration_promo_window` 的真实布尔值为 `True` 时方可豁免补差（当配置表 `sys_runtime_configs` 设为 `'false'`/`'0'`/`'off'` 时，严禁免除升级补差价）。
   - 同周期内**降级**或**主动退订**：当期已收或应计基础月费**一律不予退还**；退订后订阅状态转为 `CANCELED`（关闭自动续费），服务保留至当期结束。
   - **期中变配分段核算**：同一账期内发生套餐变更时，变更前后的用量必须分别归属各自发生时的有效套餐，按各段套餐自身的包含配额与阶梯单价分段独立计算超额费后再汇总，严禁将变更前高配额套餐下的用量混入变更后低配额套餐重算。
4. **2024 存量老租户商业兼容（`ACTIVE_LEGACY`）**：
   - 2024 年签约的 v1 老租户（`status='ACTIVE_LEGACY'`、`plan_code='LEGACY_FLAT_99'`、`schema_version=1`，含 `legacy_contract_override` 封顶条款、`legacy_discount_bps` 折扣及历史 `YUAN_STR` 字符串元账单）受存续商业合同保护，必须保持完整读取、展示与计费兼容，严禁删改或强制迁移。

## 二、多地域计量归集、时区归一化与输入幂等
1. **单笔与批量计量校验**：
   - 单笔上报（`POST /api/usage/events`）与边缘网关批量上报（`POST /api/usage/batch`）均严格要求 `quantity` 为**正整数（`> 0`）**，任何 `0` 或负数用量必须拦截返回 `400`。
2. **UTC 账期归属准则**：
   - 平台所有账期（`period_key`，格式 `YYYY-MM`）一律以事件发生时刻（`occurred_at`）**转换为标准 UTC 时间（`+00:00`）后的年月**为准（例如北京时间 `2026-12-01T01:15:00+08:00` 对应 UTC `2026-11-30T17:15:00Z`，必须归属 `2026-11` 账期而非 `2026-12`）。
3. **网关重试幂等性**：
   - 批量上报接口在遇到已入库（`usage_events` 或 `usage_events_buffer` 已存在相同 `event_id`）的重放事件时，必须幂等跳过并计入 `duplicate_count`，严禁重复累加用量或抛出主键冲突 `500`。

## 三、税率档案、数电发票（金税四期）与渠道返佣规则
1. **税率档案（`tax_profile_code`）**：
   - `CN_VAT_6_INCLUSIVE`（默认国内含税价）：标准标价已含 6% 增值税，价内拆税不额外加收（`tax_added_cents = 0`）。
   - `CN_VAT_6_EXCLUSIVE`（跨境/专票不含税协议价）：无论账单金额大小，一律在税前账单小计基础上**价外加收 6% 增值税**（`tax_cents = round(subtotal * 0.06)`，计入应付总额 `total_cents`），严禁对大额账单私自抹零税额。
   - `SG_GST_9_EXCLUSIVE`（新加坡主体不含税价）：价外加收 9% GST，属于境外税制，不支持开具中国增值税数电发票（`fapiao_eligible = False`）。
   - `EXEMPT`（历史免税/老合同）：税额为 0。
2. **数电发票价税守恒、防重与全量对账**：
   - 运营赠送金视同商业折扣，仅对已结清（`PAID`）账单的**现金实付净额**开票（全额赠送金抵扣账单不可开票）。
   - **分位守恒铁律**：开具发票的不含税金额与税额必须满足严格整数守恒 `net_amount_cents + tax_amount_cents == gross_amount_cents`（其中 `net_amount_cents = round(gross / (1 + rate))`, `tax_amount_cents = gross - net_amount_cents`），严禁因双向向下取整或浮点截断产生 1 分钱尾差。
   - **并发唯一性**：同一张账单在未红冲前至多只能存在一张有效蓝字发票（`ISSUED`），并发重复请求必须幂等返回已有发票或拦截。
   - **月度销项底账核对（`/api/fapiao/reconcile/<period_key>`）**：对接税局底账 SDK 时必须完整遍历全部分页游标，严禁在单页上限（如 50 条）处静默截断漏算。
3. **渠道伙伴返佣（`partner_commissions`）**：
   - 返佣基数严格限定为当期已结清账单的**实收现金净额**（扣除现金退款），赠送金抵扣部分不计提返佣。

## 四、钱包、争议冻结、死信重试与只读预览边界
1. **双账本守恒与原路退费**：支付优先抵扣有效赠送金，余数扣现金；退款必须严格以原支付单实付现金为上限退回现金、其余退回赠送金并恢复 `promo_grants.remaining_cents`，绝不允许赠送金洗成可提现现金。赠送金到期批处理仅扣减 `ACTIVE` 批次剩余未用额度，绝不得将钱包扣成负数。
2. **并发幂等、争议挂起与死信补扣**：
   - 在线支付、幂等重试与自动结算并发时严禁双扣或同周期重复出续费单；自动结算异常时不得将账单卡死在 `PENDING_SETTLE`（未扣款回退 `OPEN` 入 `settlement_dlq`）。
   - **争议期冻结自动扣款**：凡租户已提交争议核查（账单状态为 `DISPUTED`、或 `dispute_reason` 非空、或存在生效中的 `freeze_auto_debit` 争议单）的账单，夜间自动结算任务（`settle_open_invoices`）必须跳过自动扣款，待财务核明后再处理。
   - **死信重试差额扣款**：死信队列重试（`dlq_retry_job`）面对存在历史部分付款（`paid_cents > 0`）的账单时，**仅允许扣收剩余未付差额（`total_cents - paid_cents`）**，严禁无视已付金额再次按票面全额重复扣款。
3. **预览查询零副作用**：
   - 结算预览接口（`GET /api/invoices/<id>/settlement-preview`）属于纯只读试算操作，严禁修改数据库赠送金状态（如锁成 `LOCKED_PREVIEW`），亦严禁原地篡改全局共享的资费目录缓存对象。
4. **逾期滞纳金**：所有逾期未付账单统一加收 **5%** 滞纳金（`late_fee_cents`），无任何 VIP 豁免特权。

## 五、会计账期封账红线与跨期调账符号规范
1. `OPEN` 账期（如 `2026-11`）允许正常计量入账与错账修复；`CLOSED` 已封账账期（如 `2026-09`、`2026-10`）的所有历史账单（`invoices`）与归档总额（`archived_total_cents`）受最高审计保护，**严禁任何代码或手工 SQL 直接修改、覆写或作废**。
2. 已封账账期的延迟计量或历史差额必须在当前 `OPEN` 账期写入 `billing_adjustments` 跨期调账表。
3. **调账符号唯一标准**：`billing_adjustments.delta_cents` 采用带符号有向金额——**负数（`delta_cents < 0`，如 `-15000`）表示贷项减免/退补客户**，核销至 `OPEN` 账单时应付总额计算公式为 `new_total = max(0, total_cents + delta_cents)`；**正数（`delta_cents > 0`）表示借项补收**。切勿沿用 2024 一代系统的减号公式反转正负号！
