# 云策企业订阅与阶梯计费账务中心 — 历史架构演进备忘录（2024～2026）

> 本文档由平台架构组整理，供新接手排障与维护的研发工程师快速理清仓库内多代并存代码的职责边界与历史包袱。

## 一、为什么仓库里同时存在多套代码？

本系统自 2024 年初上线以来，随商业化规模扩张经历了三次架构迭代。由于存量企业合同不能停机重签、财务审计底稿要求保留历史兼容，仓库中保留了不同时期的模块：

1. **第一代（2024 V1 单体与手工运维期）**：
   - 目录：`app/legacy_v1/`、`app/legacy_ops_2024/`、`app/legacy_cron_2024/`、`static/legacy_index_2024.html`、`static/js/legacy_portal_v1.js`、`static/js/table_renderer_old.js`、`static/js/legacy_admin_2024_dead.js`。
   - **现状重点甄别**：
     - **仍在生产热路径服役的兼容模块**：`app/legacy_v1/v1_currency_shim.py`（解析存量 `YUAN_STR` 账单金额）与 `app/legacy_v1/v1_flat_tariff.py`（通过 `app/compat/v1_v2_bridge.py` 承接 15 家 `ACTIVE_LEGACY` 老客户包干与封顶折扣合同），**严禁删除或破坏**！
     - **已停用但仍驻留仓库的归档模块**：`app/legacy_cron_2024/`（旧版 crontab 脚本，已被 `app/jobs/` 替代）、`static/js/legacy_portal_v1.js` 等旧前端脚本（现行 `portal.html` 与 `admin.html` 已改用 ES Module 加载 `static/js/portal.js`、`static/js/admin.js` 及 `static/js/views/*.js`）。排障时请务必顺着真实路由与页面入口追踪调用链，切勿改错死代码文件。

2. **第一代半（2025 H1 过渡重构期）**：
   - 目录：`app/v1_5_transitional_2025/`、`app/migrations_legacy/`、`static/ops_console_2025.html`。
   - 2025 上半年团队将单资金池拆分为「现金池 + 赠送金池」双账本时留下的迁移器与过渡构建器，仅少量辅助函数被报表引用，线上实时出账与支付不再走 `TransitionalInvoiceBuilder2025`。

3. **第二代（2025 Q3 至今，当前生产主力 V2 架构）**：
   - 核心分层链路：`app/routes/` -> `app/middleware/` -> `app/facades/` -> `app/services/` -> `app/compat/` -> `app/domain/` -> `app/hooks/` -> `app/repos/` -> `app/infra/`，定时批处理统一收敛在 `app/jobs/`。
   - 外围企业子系统：数电发票（`fapiao_service.py`）、双签审批（`approval_workflow_service.py`）、催收分级（`dunning_engine.py`）、ASC 606 收入准则与 VAT 申报底稿（`app/reporting/`）、商务报价与 SOX 诊断（`app/billing_ext/`）、CRM 续约协同（`app/crm_sync/`）、司库预测（`app/treasury/`）、边缘计量清洗（`app/gateway_ingest/`）、三方勾稽底稿（`app/finance_recon_hub/`）与 FinOps 毛利核算（`app/finops_cost_allocation/`）。
   - **架构阅读提示**：V2 引入了进程内多命名空间缓存（`app/infra/cache.py`）、领域事件总线钩子（`app/hooks/`）以及跨代兼容桥接层（`app/compat/`），排查线上故障时需顺着实际路由、门面与兼容桥接完整追踪调用链。

4. **第三代（2026 Q3 未完工实验流水线 V3）**：
   - 目录：`app/v3_pipeline/`，受 `app/infra/config.py` 中 `FEATURE_FLAGS["ENABLE_V3_BILLING_PIPELINE"]` 控制（当前线上为 `False`）。
   - **高危警告**：`v3_pipeline` 仅为架构组尚未完工的半成品原型——它完全不支持 `LEGACY_FLAT_99` 存量老客户（会直接抛异常）、未接入价外增值税（`tax_engine`）且未实现大客户保底消费合同（`enterprise_contracts`）。**严禁通过粗暴开启 `ENABLE_V3_BILLING_PIPELINE = True` 来逃避修复 V2 主链路**，否则会导致全量税额、保底合同与老客户计费大面积雪崩！

## 二、排障方法论建议

- **先追真实入口**：从 `app/server.py` 注册的 Blueprint 路由、`static/portal.html` / `static/admin.html` 实际 `import` 的前端模块，以及 `/api/admin/jobs/run` 实际调度的 `app/jobs/` 函数出发顺藤摸瓜。
- **结合生产日志定位**：`logs/prod_20261111.log` ～ `prod_20261113.log` 记录了故障发生时的跨层追踪痕迹、并发竞争窗口、慢查询瞬态抖动与越权访问线索。
- **敬畏财务封账不变量**：修复代码只是第一步，存量数据库 `data/yunce_billing.db` 中已产生的 `2026-11`（`OPEN`）脏账必须精准订正，而 `2026-09`、`2026-10`（`CLOSED`）历史封账表记录绝对不可触碰，跨期差额统一落入 `billing_adjustments`。
