# 《遗留救火 · 复杂暗病排障基准》（legacy-rescue-xiaonuo v4.1）

> **一句话定位**：单旗舰级、多代架构交织、零源码剧透、埋设 60 个独立跨层暗病（含 40% 零工单潜伏暗病）、68 条去技术化随机混排一线反馈、16 个活跃目录高仿未挂载孪生文件与 240 租户全库无点名跨表脏账的高区分度企业遗留系统（“屎山”）深度排障评测基准。

## 核心特点
1. **零剧透高仿真多代企业遗留代码迷宫（530+ 个文件、52,000+ 行源码/文档/生产日志）**：围绕“云策企业订阅与阶梯计费账务中心”，完整还原 2023 初创种子归档死代码、2024 第一代包干单体与工程师个人孤岛、2025 架构委员会过度设计抽象链与混合双写过渡层、主力 V2 纵深业务链、启动期运行时兼容与紧急热补丁、第三方金税与外汇清分模块、未完备的 V3 实验管线，以及混入活跃业务目录的 **16 个高仿未挂载孪生文件**；彻底剥离自白式缺陷注释与过期制度文件名标记，要求模型必须靠真实调用链追踪、制度签发日期核验与日志/账本取证定位根因。
2. **60 项独立根因暗病（40% 零工单纯潜伏）+ 68 条去技术化洗牌反馈 + 48 项无点名全库脏账审计**：
   - **60 个独立故障单元（`BUG-01`～`BUG-60`）**：横跨计费引擎、双池钱包结算、银企外汇清分、金税数电开票与跨期调账、复式总账与递延收入摊销、渠道二级分润与催收停机风控、安全导出与多视图前端**七大业务域**；其中 **24 个（40%）为完全不在反馈单提及的零工单潜伏暗病**，必须通过生产错误日志取证、总账借贷试算不平或同构调用链深挖才能揪出。
   - **68 条纯业务视角随机混排反馈（`F01`～`F68`）**：彻底剔除代码路径、数据库表名、配置开关及受灾租户 ID 暗示，将 42 条模糊业务投诉与 **26 条高迷惑性伪需求/无标记旧制度误导/合规越界施压**完全随机打乱混排。
   - **240 家租户、34 张表线上 SQLite 快照**：选手需自己编写全库对账脚本筛查并修平 `2026-11` 开放期 **44 处行级异构脏账 + 3 大开放期子账本（复式总账、渠道返佣、递延摊销）**，同时严守 `2026-09`/`2026-10` 历史封账字节级零修改铁律并补齐 **2 笔跨期贷项调账单**（共 48 项核验）。
3. **高区分度严格计分梯度（`A(62, 二次方梯度) + B(扣分闸门) + C(12) + T(6) + D(20) = 100`）**：
   - **A 层全或无硬判 + 陡峭轮次折扣（`1.00 / 0.85 / 0.70`）+ 二次方凸梯度（`62` 分：`A1=45`、`A2=17`）**：零工单潜伏暗病按 `1.3x` 加权，且采用二次方凸函数放大高覆盖率与半吊子修复之间的分差。
   - **B 层 24 项强耦合防误伤闸门（`0` 分起扣，每破坏 1 项倒扣 `3.0` 分）+ `0.65` 高压红线全局惩罚**：8 枚强耦合连带损伤雷与高频修复路径共用同一函数，一刀切粗暴修法将直接触发倒扣。
   - **C 层外科手术收敛度与细粒度突变测试（`12` 分：`C1=6`、`C2=6`）**：需至少 `18` 个在未修复原件红灯、修复件绿灯的独立测试方法拿满 `C2`，误改未挂载死代码/孪生文件按文件数倒扣 `C1`。
   - **T 层耗时效率分（`6` 分：满分阈值 `15` 分钟，半衰期 `45` 分钟）+ 修复质量与防误伤非线性封顶**。
   - **D 层匿名盲评硬锚点封顶表（`20` 分）**：事实卡自动置顶客观覆盖率并锁定评委打分上限，严禁端水与印象高分。
4. **两阶段严格解耦（盲评先行 → 一键统一定稿出榜）**：被测模型收到“你是被测模型，开始测试”后一条龙完成起局、排障、门禁巡检、封包与匿名盲评打包（不提前生成正式得分）；独立评委盲评后，由发起人运行 `python leaderboard/finalize.py` 统一完成客观分定稿与总榜合成。

## 一局怎么跑（被测模型一条龙流程）

详细规范见 [AGENTS.md](AGENTS.md)。被测模型在仓库根目录按顺序执行：

```sh
# 1. 起局：自动分配 <Model>-r1 沙盒并打下不可伪造的起始时间戳 t0
python src/cli/start_rescue.py --model <你的真实模型名>

# 2. 沙盒内排障并提交预发定性门禁（最多 3 轮；七大业务域仅回传「已闭环 / 仍有异常未闭环」定性信号，首轮闭环 1.00x、二轮 0.85x、三轮 0.70x）
python src/cli/checkpoint_round.py --sandbox sandbox/<run_id> --round 1 --summary "首轮全库对账与跨层排障"

# 3. 收工：最后一轮完成后打下结束时间戳 t1、冻结交付快照并记录词元消耗
python src/cli/finish_rescue.py --sandbox sandbox/<run_id> --tokens-input 85000 --tokens-output 18000 --commands-count 45

# 4. 收尾：校验计时窗口并生成匿名盲评包（不提前写入正式评分）
python src/scoring/timing_audit.py runs --strict
python src/scoring/judge_pack.py --runs runs/<run_id>
```

## 盲评阶段与最终一键出榜

```sh
# 1. 盲评阶段：独立评委仅看 leaderboard/blind/<pack_id>/ 脱敏事实卡（严格遵守客观覆盖率硬锚点封顶表）并提交 D 分（D1:0-8, D2:0-6, D3:0-6）
python src/scoring/judge_submit.py --pack-dir leaderboard/blind/<pack_id> --case-id case-01 \
  --judge-id judge-A --judge-model gpt-5 --D1 8 --D2 6 --D3 6 --evidence "[A1:60/60, Silent:24/24, A2:48/48, B:24/24]"

# 2. 最终一键出榜：所有盲评完成后手动运行，统一执行脚本客观分定稿（80分）+ 盲评合成（20分） -> leaderboard/scores.md
python leaderboard/finalize.py
```
